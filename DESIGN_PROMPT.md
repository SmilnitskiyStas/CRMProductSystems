## 🖥️ ЧАСТИНА 1 — WEB CRM (React + TailwindCSS)

### Контекст продукту
ShelfGuard — B2B SaaS платформа для управління термінами придатності товарів у
магазинах і мережах. Користувачі: менеджери магазинів, директори мереж, комірники.
Робота з даними критична — кольорові статуси (safe/warning/critical/expired) є
основою інтерфейсу. Продукт українськомовний.

---

### Загальний стиль
- **Тема:** темна (dark mode) як основна, світла як опція
- **Характер:** індустріальний, точний, без зайвих прикрас — це інструмент
  для роботи, не маркетинговий сайт
- **Не робити:** градієнти у стилі SaaS-лендінгів, пастельні кольори,
  округлі bubble-картки, фіолетово-рожеві акценти
- **Робити:** чіткі межі, функціональна щільність, контрастні статусні кольори

## 📱 ЧАСТИНА 2 — MOBILE APP (React Native Expo + NativeWind)

### Контекст використання
Мобільний додаток для мерчандайзерів і комірників. Використовується в русі,
часто однією рукою, у приміщеннях з різним освітленням (яскраве торговельне,
темний склад). Основна дія — сканування штрихкоду + швидке внесення даних.

### Стиль мобільного
- Та ж темна палітра що і web — єдиний бренд
- Більші touch targets (мінімум 48px)
- Мінімум тексту, максимум іконок і кольорів
- Bottom navigation (не hamburger)
- Нативний feel: safe area, haptic feedback

## 🎨 ДОДАТКОВІ ВИМОГИ ДО ДИЗАЙНУ

### Іконографія
Використовувати один набір іконок: **Lucide Icons** або **Phosphor Icons**.
Не змішувати різні стилі іконок.

### Анімації та взаємодія
- Hover стани на всіх інтерактивних елементах
- Loading skeleton замість спінерів де можливо
- Toast сповіщення (правий нижній кут на web, верх на mobile)
- Confirmation dialog для небезпечних дій (списання, видалення)
- Status badge — легкий пульс для CRITICAL та EXPIRED

### Адаптивність Web
- Desktop: sidebar + content (основний)
- Tablet (1024px): collapsed sidebar (іконки)
- Mobile web: не пріоритет (є нативний додаток)

### Компоненти які точно потрібні
```
Web:
  - StatusBadge (safe/warning/critical/expired/needs_check)
  - DaysLeftBadge (число + колір залежно від кількості)
  - StockTable (dense, з сортуванням і фільтрами)
  - MetricCard (велика цифра + назва + колір)
  - ActionDropdown (Знижка/Перемістити/Списати)
  - FloorPlanCanvas (drag&drop)
  - TenantCard (для Super Admin)

Mobile:
  - StatusCard (2×2 grid)
  - ScanButton (велика CTA)
  - TaskListItem (статус + назва + дні + стрілка)
  - BatchForm (форма партії)
  - ReceiptListItem (прогрес прийомки)
  - SuggestionCard (пропозиція дії)
```

### Що НЕ робити
- Не використовувати градієнтний purple/pink фон
- Не використовувати Inter як єдиний шрифт (нудно)
- Не робити всі картки однаково округлими і "повітряними"
- Не ховати статусні кольори — вони є головним комунікаційним інструментом
- Не робити кнопки "Списати" і "Зберегти" однакового вигляду
