### BUG-253-001 — ScheduleShift missing RLS on `TenantId` not enforced for cross-schedule shift lookup
- **Severity:** Medium
- **Location:** `ScheduleRepository.GetShiftByIdAsync` — queries `sh.TenantId == tenantId` in LINQ, but `GetShiftsByUserAsync` (for my-shifts) queries only by `UserId + TenantId + date range`. This is correct.
- **Actual Bug:** In `UpdateScheduleAsync`, the service loads the schedule via `GetByIdWithShiftsAsync` which is correctly RLS-scoped. However, in `AddShiftAsync`, the `dto.LocationId` for the new shift is accepted without validating it belongs to the same tenant. A manager could potentially add a shift referencing a LocationId from another tenant if the UUID is known. The DB FK would not catch cross-tenant issues because RLS only runs for the current tenant's session context.
- **Status:** ❌ BUG — `CreateShiftDto.LocationId` is not validated to belong to the current tenant before insert. Consider adding a tenant-scoped location existence check in `ScheduleService.AddShiftAsync`.

### BUG-251-001 — Internal comments visible to non-managers in TicketDetailDto if IsInternal filter is bypassed
- **Severity:** Medium / Security
- **Location:** `TicketService.ToDetailDto` — `t.Comments.Where(c => isManager || !c.IsInternal)` — this correctly filters internal comments for non-managers in `GetByIdAsync`. However, `GetPagedAsync` (manager-only endpoint) loads all comments via `Include(t => t.Comments)` and passes to `ToDto` which exposes `CommentCount` (total count including internal). For the list view, `CommentCount` leaks the count of internal comments to managers (which is fine — they should see it). But the `GetByIdWithCommentsAsync` used in `GetById` includes the Author via `ThenInclude(c => c.Author)`, while `GetByIdAsync` used in `UpdateAsync` and `AddCommentAsync` does NOT include Author ThenInclude — so the `Author?.FullName` in `ToDto` after update will be empty string for comments.
- **Impact:** After `PUT /api/service-desk/{id}`, the response `ToDto(reloaded!)` uses `reloaded.Comments` loaded WITHOUT `ThenInclude(c => c.Author)`, causing `CreatedByName` equivalent to return empty string in `CommentCount` (not shown), but the main issue is if the caller checks `AssignedToUser?.FullName` — that IS loaded via Include. Comments are not in the list DTO so this is low-impact.
- **Status:** ❌ BUG (low severity) — `GetByIdAsync` in TicketRepository loads Comments without `.ThenInclude(c => c.Author)`, while `GetByIdWithCommentsAsync` does. After `UpdateAsync`, `ToDto(reloaded!)` is called — the `CommentCount` will be correct (uses `.Count`), but any future expansion of `ToDto` to include comment details would expose empty author names.

### TC-251-013 (Додатково) Паралельне існування двох контролерів: api/support та api/service-desk
- **Expected:** No conflict
- **Actual (static):** Both `SupportController` (route `api/support`) and `ServiceDeskController` (route `api/service-desk`) are registered simultaneously. They use different services (`ISupportService` vs `ITicketService`) but write to the same `support_tickets` table. The old `api/support` uses `SupportMessage` (legacy messages), the new `api/service-desk` uses `TicketComment`. **Risk:** a ticket created via `api/support/tickets` will not have a `Title`, `Description`, or `Number` populated (these have `defaultValue: ""` and `defaultValue: 0` in migration). Calling `GET /api/service-desk` will surface these legacy tickets with empty titles.
- **Status:** ⚠️ WARNING — Legacy `api/support` controller creates tickets without the new required fields (Title, Description default to "" in DB). These surface in the new Service Desk UI with blank titles.

## Bugs Found

### BUG-253-001 — Shift LocationId not tenant-validated
- **Severity:** Medium  
- **Module:** TASK-253 Schedules  
- **File:** `backend/ShelfGuard.Application/Features/Schedules/ScheduleService.cs`, method `AddShiftAsync`  
- **Description:** `CreateShiftDto.LocationId` is accepted and written to DB without verifying the location belongs to the same tenant. An authenticated manager from Tenant A who knows a Location UUID from Tenant B could create a shift referencing it.  
- **Fix:** Add `var locationExists = await _locationRepo.ExistsForTenantAsync(dto.LocationId, tenantId, ct); if (!locationExists) return (null, "Location not found.");` before creating the shift. Requires injecting ILocationRepository into ScheduleService.

### BUG-251-001 — TicketComment.Author is null after UpdateAsync reload
- **Severity:** Low  
- **Module:** TASK-251 Service Desk  
- **File:** `backend/ShelfGuard.Infrastructure/Data/Repositories/TicketRepository.cs`, method `GetByIdAsync`  
- **Description:** `GetByIdAsync` includes `Comments` but NOT `.ThenInclude(c => c.Author)`. After `UpdateAsync`, `ToDto(reloaded!)` is called; if the caller in future expands `ToDto` to include comment details, author names would be empty. Currently `CommentCount` is the only comment field in `TicketDto`, so this is latent but not currently user-visible.  
- **Fix:** Add `.ThenInclude(c => c.Author)` to `GetByIdAsync` in `TicketRepository`, or use `GetByIdWithCommentsAsync` in `UpdateAsync`.

## Code Review Findings

### CF-001 Phone search uses `Contains` vs `ILike` inconsistency (Customers)
- **File:** `CustomerRepository.GetPagedAsync`  
- **Issue:** `c.Phone.Contains(term)` uses LIKE with case-sensitive matching on PostgreSQL, while `EF.Functions.ILike` is used for Name/Email. Phone search will be case-sensitive (irrelevant for phone numbers, but inconsistent with the pattern).  
- **Severity:** Cosmetic / Low

### CF-002 Schedule WeekStart not validated to be a Monday (Schedules)
- **File:** `ScheduleService.CreateScheduleAsync`  
- **Issue:** `WeekStart` is accepted as any `DateOnly` value without validation that it falls on a Monday. The entity docstring says "Monday of the week this schedule covers" but this is not enforced.  
- **Severity:** Low — could cause confusing weekly views if data is entered with wrong day.  
- **Fix:** `if (dto.WeekStart.DayOfWeek != DayOfWeek.Monday) return (null, "WeekStart must be a Monday.");`

### CF-003 Category and Priority values not validated in Service Desk (Service Desk)
- **File:** `TicketService.CreateAsync`  
- **Issue:** `dto.Category` and `dto.Priority` are stored as-is without validation against `SupportTicketCategory` / `SupportTicketPriority` constants. Any string (e.g. "foo") will be accepted and stored.  
- **Fix:** Validate against the defined constants before persisting.

### CF-004 ScheduleShift has no `UpdatedAt` field (Schedules)
- **File:** `backend/ShelfGuard.Domain/Entities/ScheduleShift.cs`  
- **Issue:** `ScheduleShift` has no `UpdatedAt` timestamp. After `UpdateShiftAsync`, there is no audit trail of when the shift was last modified.  
- **Severity:** Low — missing audit data.

### CF-005 No unique constraint on (TenantId, LocationId, WeekStart) in work_schedules (Schedules)
- **File:** `backend/ShelfGuard.Infrastructure/Migrations/20260618203029_AddWorkforceSchedules.cs`  
- **Issue:** Index `idx_work_schedules_tenant_location` on `(TenantId, LocationId, WeekStart)` is NOT UNIQUE. Multiple schedules for the same location and week can coexist in "draft" status, which may be intentional (multiple drafts), but may also cause confusion. Service does not check for duplicates.  
- **Severity:** Low — by design if multiple drafts are allowed, but worth documenting.

### CF-006 Duplicate service desk APIs — legacy `api/support` not deprecated (Service Desk)
- **File:** `backend/ShelfGuard.Api/Controllers/SupportController.cs`  
- **Issue:** The legacy `SupportController` at `api/support/tickets` remains active alongside `ServiceDeskController` at `api/service-desk`. Tickets created via the old API will surface in the new API with empty `Title`/`Description` (DB default ""). No deprecation header or migration path is in place.  
- **Severity:** Medium — creates data quality issues and user confusion.  
- **Fix:** Either deprecate the legacy controller (add `[Obsolete]` and return 410 Gone with a message) or migrate it to delegate to `ITicketService`.
