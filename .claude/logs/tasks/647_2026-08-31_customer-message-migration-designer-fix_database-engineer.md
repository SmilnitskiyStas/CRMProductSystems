## Fix — one file created

`backend/ShelfGuard.Infrastructure/Migrations/20260830143000_AddCustomerMessageCampaignSnapshots.Designer.cs`

Derived mechanically from `20260830175708_AddCustomerMessageContentReference.Designer.cs`
(the snapshot as of `175708`) by reverse-applying `175708`'s `Up()`. Generated by script so
the remaining ~8850 lines stay byte-identical; UTF-8 BOM + CRLF preserved. Full diff vs. the
source file:

1. **Header** — `partial class AddCustomerMessageContentReference` →
   `partial class AddCustomerMessageCampaignSnapshots`.
   ⚠️ `[DbContext(typeof(AppDbContext))]` / `[Migration(...)]` were **dropped, not renamed**:
   the hand-written `20260830143000_...cs` already declares both on the same partial class,
   and both are `AllowMultiple = false` → repeating them in the Designer is a hard `CS0579`
   build error. A comment in the file records this. EF resolves the migration id from the
   type (partial declarations merge), so discovery is unaffected — confirmed by
   `migrations list` / `migrations script` below. This deviates from EF's usual
   attributes-in-Designer convention only because the `.cs` is hand-written; the alternative
   (moving the attributes) would mean editing the other session's file, which is out of scope.

2. **Reverse of `175708` `AddColumn` ×4** — removed 4 properties from the
   `ShelfGuard.Domain.Entities.CustomerMessageCampaign` block only:
   `ContentId` (uuid?), `ContentImageUrl` (varchar 2000), `ContentTitle` (varchar 200),
   `ContentType` (varchar 30).

3. **Reverse of `175708` `DropIndex`** — added `b.HasIndex("TenantId");` back, placed between
   `HasIndex("CreatedByUserId")` and the `("TenantId","CreatedAt")` composite (EF snapshot
   index order = property-count, then property names). No `.HasDatabaseName(...)`: the EF
   default for `HasIndex("TenantId")` on `customer_message_campaigns` is exactly
   `IX_customer_message_campaigns_TenantId`, which the generated SQL confirms.

Nothing else changed. `customer_message_recipients` and every other entity untouched;
`060145`-era columns (`DeliveryMode`/`ScheduledAt`/`SubmittedAt`) correctly absent — verified
