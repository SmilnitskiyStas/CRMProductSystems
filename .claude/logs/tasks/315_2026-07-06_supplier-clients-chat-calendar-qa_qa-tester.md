### Знахідка (не бага, архітектурне зауваження)
`GET /api/supplier-cabinet/clients` (і так само `/tasks`, `/staff`, `/chat/sessions`) не має
server-side перевірки permission — тільки клас-рівня `AppPolicies.SupplierCabinet` (роль
`supplier_admin`/tenant-belonging), без перевірки конкретного permission (`client_management`
тощо). Restricted Staff, звернувшись напряму до API (не через UI), отримує повні дані —
`200 OK` з повним списком клієнтів/завдань/чатів. **Це наявний системний патерн у всьому
`SupplierCabinetController`, не щось нове в TASK-312-314** — підтверджено ідентичною поведінкою
на `/tasks` і `/staff`. UI-гейт (Sidebar + сторінка) захищає від випадкового доступу, але не від
навмисного виклику API. Рекомендація на майбутнє (не блокер для цього релізу): додати
`RequireSupplierPermission` атрибут-фільтр аналогічно `RequireModule`.

## 2. Чат постачальник↔клієнт — PASS

- Клієнт ініціює: `POST /api/marketplace/suppliers/{id}/chat/messages` → `201`, сесія
  auto-created. Постачальник бачить через `GET /chat/sessions` і читає повідомлення.
- Постачальник відповідає: `POST /api/supplier-cabinet/chat/sessions/{clientTenantId}/messages`
  → `201`, клієнт бачить відповідь через `GET /api/marketplace/suppliers/{id}/chat/messages`.
  Обидва напрямки підтверджені реальними HTTP-раундтрипами.
- **RLS-ізоляція (3-й tenant):** Client Two спілкується з тим самим supplier — окрема сесія
  (`c3dd0176-...`) від сесії Client One (`885ae709-...`). Повідомлення Client Two НЕ з'явились
  у списку повідомлень Client One і навпаки. `GET /chat/sessions` постачальника показує рівно
  2 окремі сесії з правильним `otherTenantName` для кожної. Крос-клієнтський leak відсутній.
- Non-supplier tenant (Client Two) на supplier-side ендпоінтах → `403` (class-level policy).
- Валідація: порожній body → `400 "Message body is required."`; пробіли-тільки → той самий
  400 (trim); 4001 символ → `400 "...cannot exceed 4000 characters."`; рівно 4000 символів →
  `201` (межове значення приймається). Всі edge-cases коректні.
- Неіснуючий `supplierId` в клієнтському чат-ендпоінті → `404 {"error":"Supplier not found."}`.
- UI: чат-панель постачальника (`SupplierClientChatPanel`) відкривається з правильного рядка
  клієнта (`ClientsTab.tsx`), показує правильний тред (перевірено обидва клієнти окремо,
  не переплутані), `isMe` рендериться вірно (своє праворуч без імені, чуже — з іменем).
  Публічні відгуки (`GET /suppliers/{id}/reviews`) показують лише `reviewerName`, без tenant id
  — конфіденційність не порушена.
- Polling (3000ms React Query): підтверджено працює на **фокусованій** вкладці (initial fetch +
  invalidation on send — обидва підтверджені). На фонових/неактивних вкладках (`document.hidden
  === true`) браузер тротлить `setInterval`, тому 3s-інтервал не спрацьовує вчасно — це
  стандартна поведінка браузера для background tabs, не дефект коду фічі.
