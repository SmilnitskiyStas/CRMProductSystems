# Landing Page — бриф і чек-лист матеріалів

**Статус:** реалізація (2026-07-10, TASK-333 lead endpoint + TASK-334 landing).

**Відповіді користувача (2026-07-10):**
1. Назва: **ShelfGuard by AgruSystems**
2. Аудиторія: **магазини / мережі** (основний акцент)
3. CTA: на наш розсуд → форма заявки → POST /api/public/leads (зберігання в БД)
4. Тарифи: «за запитом»
5. Соц. доказ: пропустити
6. Логотип: немає — створюємо самі (SVG)
7. Ескізу немає — дизайн на нас: темна тема (як застосунок), професійний B2B SaaS стиль

**Наявні матеріали:** `img/` у корені репо (копіюються у frontend/public/landing/):
dashboard-1.jpg (повний дашборд зі статус-картками Safe/Warning/Critical/Expired — hero),
dashboard-2.jpg (карта магазину, вузька стрічка), inventory-1.jpg (таблиця партій з
простроченими), inventory-2.jpg (партії «Норма»), analytics-1.jpg (donut + картки),
analytics-2.jpg (бар-чарт по категоріях). Всі 1280px, темна тема, укр. інтерфейс, демо-дані.

## Технічний план (рішення вже ухвалені, від користувача нічого не треба)

- Роут `/` у frontend (Next.js App Router), SSG/SSR — лендінг має явну SEO-вимогу (виняток
  з правила CSR у CLAUDE.md). Залогінені користувачі → redirect на /dashboard.
- Мова: українська. SEO meta + OpenGraph + favicon.
- Стек: той самий Tailwind + shadcn/ui, без нових CSS-фреймворків.
- Скриншоти оптимізувати через next/image (WebP), lazy-load нижче фолда.
- Форма заявки (lead): POST на новий публічний API endpoint з rate limit → збереження в БД
  + нотифікація в Telegram (бот уже працює). Без сторонніх платних сервісів.

## Пропонована структура сторінки (чернетка, узгодити)

1. **Hero** — заголовок-цінність (контроль термінів придатності + автозамовлення + каса),
   CTA «Залишити заявку», головний візуал (скриншот дашборда або генерований hero).
2. **Проблема → рішення** — списання простроченого, ручні замовлення, хаос залишків.
3. **Можливості (6-8 карток)**: FEFO-контроль термінів · AI-автозамовлення (Claude) ·
   POS-каса з ПРРО (Checkbox) · B2B marketplace постачальників · IoT-моніторинг (температура/вага) ·
   Аналітика і KPI · Мобільний застосунок (сканер штрихкодів) · Графіки персоналу / HR.
4. **Для кого** — таби/секції за типом бізнесу: продуктові магазини й мережі, автосервіси,
   виробництво, склади (module activation з v4 це підтримує).
5. **Скриншоти інтерфейсу** — карусель/грід web + mobile.
6. **Як почати** — 3 кроки (заявка → онбординг → робота). Самореєстрації немає, онбординг через нас.
7. **Тарифи** — якщо користувач дасть; інакше «за запитом».
8. **FAQ + контакти + форма заявки.**

## Що потрібно від користувача

### A. Скриншоти (пріоритет — перші 5)
Формат: повноекранний браузер 1920×1080, світла тема, УКР інтерфейс, наповнені демо-дані
(НЕ порожні таблиці, НЕ реальні клієнтські дані), без DevTools/закладок. PNG.

1. Dashboard (головна після логіну) — hero-кандидат
2. Shelf/FEFO — список партій зі статусами термінів (зелений/жовтий/червоний)
3. AI-замовлення — сторінка з пропозиціями автозамовлення
4. POS-каса — екран продажу з кошиком
5. Аналітика — сторінка з графіками
6. Marketplace — каталог постачальників
7. IoT — датчики температури
8. Графіки персоналу
9. Mobile (3-4 скріни з телефона/емулятора, вертикальні): сканер, стоки, POS, дашборд

### B. Рішення по контенту (відповісти текстом)
1. **Назва на лендінгу**: ShelfGuard, AgruSystems чи обидві (ShelfGuard by AgruSystems)?
2. **Головна аудиторія** (порядок акцентів): магазини/мережі? автосервіси? виробництво?
3. **CTA/ліди**: куди падає заявка — Telegram-нотифікація + БД достатньо? Який контакт
   показувати (email, телефон, Telegram)?
4. **Тарифи**: показувати ціни чи «за запитом»?
5. **Соц. доказ**: чи є клієнти/цифри, які можна назвати (N магазинів, M SKU під контролем)?
   Якщо ні — пропускаємо секцію.
6. **Брендинг**: чи є логотип (SVG/PNG)? Фірмові кольори чи беремо з застосунку?
7. **Ескіз/референси**: користувач згадував ескіз — надати фото/файл + 1-2 лендінги, які
   подобаються стилістично.

### C. Генеровані візуали (nano banana / higgsfield.ai — генерує користувач, промпти дамо)
Потрібні лише якщо хочемо «живі» фото поверх скриншотів. Кандидати:
- Hero: менеджер із планшетом біля полиць свіжих продуктів, на екрані — дашборд (скриншот
  можна вклеїти генератором поверх екрана планшета)
- Секція IoT: датчик на холодильній вітрині
- Секція POS: каса в магазині
Вимоги: 16:9 ≥1920px для hero, реалістичний стиль, без тексту на зображенні (текст ляже з HTML).
Промпти підготуємо в сесії реалізації після відповідей блоку B.
